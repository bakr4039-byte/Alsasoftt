# حاضر للجوال — المرحلة 1 (نموذج أولي)

هذا نموذج أولي عملي يوضح الاتجاه المقترح: خلفية (backend) حديثة + تطبيق جوال Flutter،
بدل الاعتماد المباشر على ملفات Access الحالية. البيانات هنا **تجريبية بالكامل** لغرض العرض،
وليست بيانات حقيقية من نظامك الحالي.

## البنية

```
hader-mobile/
├── db/schema.sql        مخطط قاعدة البيانات المستهدف (PostgreSQL) — مرجع للبنية الكاملة
├── backend/              واجهة برمجية (FastAPI) — تُنشر مجانًا على الإنترنت (Render)
└── mobile/                تطبيق الجوال (Flutter) — يتصل بالـ API عبر الإنترنت
```

## تشغيل الخلفية (Backend) عبر الإنترنت — الطريقة الموصى بها

بدل تشغيل السيرفر على جهازك (اللي واجه مشكلة `ERR_CONNECTION_REFUSED`)، ننشره مجانًا على
الإنترنت بحيث يشتغل بشكل دائم وتقدر توصله من أي جهاز أو محاكي بدون إعدادات شبكة محلية.
كل الخطوات التالية عبر مواقع مجانية **بدون بطاقة ائتمان**، وأنت تسويها بنفسك من حسابك (ما نطلب منك أي كلمة مرور أو مفتاح تحطه هنا).

### 1) قاعدة بيانات مجانية دائمة — Neon (PostgreSQL)

1. روح [neon.tech](https://neon.tech) وسوّي حساب مجاني (بدون بطاقة).
2. أنشئ مشروع جديد (Project) — أي اسم.
3. من لوحة المشروع، انسخ **Connection string** (يبدأ بـ `postgresql://...` أو `postgres://...`).
   خله جاهز، بتحتاجه بالخطوة 3.

### 2) رفع كود الخلفية على GitHub (بدون أوامر git)

1. سوّي حساب مجاني على [github.com](https://github.com) إذا ما عندك.
2. أنشئ مستودع (Repository) جديد، خاص أو عام، بأي اسم (مثلاً `hader-api`).
3. بصفحة المستودع اضغط **Add file → Upload files**، وبعدين اسحب **كل محتويات مجلد
   `backend/`** (الملفات والمجلدات اللي جواه: `app/`, `requirements.txt`, `render.yaml`) —
   بحيث تكون هذي الملفات في جذر المستودع مباشرة، مو داخل مجلد `backend` بالمستودع. احفظ (Commit).

### 3) نشر الخادم مجانًا — Render

1. روح [render.com](https://render.com) وسجّل حساب مجاني بربطه مع حساب GitHub (بدون بطاقة).
2. اضغط **New +** → **Blueprint**، واختر المستودع اللي رفعته بالخطوة السابقة.
   Render بيقرأ ملف `render.yaml` تلقائيًا ويجهّز كل الإعدادات.
3. بيطلب منك قيمتين (Environment Variables) — عبّيهم بنفسك بلوحة Render مباشرة:
   - `DATABASE_URL` → الصق رابط Neon اللي نسخته بالخطوة 1.
   - `HADER_SECRET_KEY` → أي نص عشوائي طويل تختاره أنت (مثال يمكن تستخدمه:
     `35c3bc6cf11820bc1a3460e6247acaa07f53d8984affc33a8fe1e724c995db05` — أو ولّد نص عشوائي غيره، المهم يكون طويل وسري).
4. اضغط **Apply/Deploy**. أول نشر ياخذ بضع دقائق (يثبّت المكتبات).
5. بعد اكتمال النشر، Render يعطيك رابط عام شبيه بـ:
   `https://hader-api.onrender.com`
   افتحه بالمتصفح على `/health` (يعطي `{"status":"ok"}`) وعلى `/docs` (وثائق تفاعلية).

**ملاحظة عن السرعة**: النسخة المجانية من Render "تنام" بعد 15 دقيقة بدون طلبات، وأول طلب بعد النوم ياخذ حوالي دقيقة يصحّي فيها — هذا طبيعي بالخطة المجانية، مو خلل.

**تعبئة تلقائية للبيانات التجريبية**: أول ما يشتغل الخادم على قاعدة فاضية، يعبّي بيانات
تجريبية وحسابات دخول تلقائيًا (نفس الجدول أدناه) — ما تحتاج تشغّل أي أمر يدوي. هذا خاص
بنسخة التجربة فقط؛ النسخة النهائية (بقرارك) تبدأ فاضية بدون بيانات وهمية — يمكن تعطيل
هذا السلوك لاحقًا بإضافة متغير بيئة `DISABLE_AUTO_SEED=1` بلوحة Render.

## تشغيل تطبيق الجوال (Flutter)

يتطلب تثبيت [Flutter SDK](https://docs.flutter.dev/get-started/install) على جهازك أولًا.

```bash
cd mobile
flutter pub get
flutter run --dart-define=HADER_API_BASE_URL=https://hader-api.onrender.com
```

- استبدل `https://hader-api.onrender.com` برابط Render الفعلي اللي حصلت عليه بالخطوة 3 أعلاه.
- بهذي الطريقة التطبيق يشتغل على أي جهاز أو محاكي (أندرويد أو آيفون) بدون أي إعداد شبكة محلي — كل شي يمر عبر الإنترنت.

## (بديل) تشغيل محلي على جهازك — لو تفضل ذلك لاحقًا

```bash
cd backend
pip install -r requirements.txt
python -m app.seed          # تعبئة بيانات تجريبية يدويًا (اختياري — التشغيل عبر الإنترنت يعبّي تلقائيًا)
uvicorn app.main:app --reload --host 0.0.0.0 --port 8811
```
ثم: `flutter run --dart-define=HADER_API_BASE_URL=http://10.0.2.2:8811` (لمحاكي أندرويد).

## ما الذي يعمل فعليًا في هذا النموذج

**للمعلم:**
- تسجيل دخول عبر JWT (بكلمات مرور مشفّرة بـ bcrypt — لا نص صريح)
- عرض الملف الشخصي (القسم، الوظيفة)
- عرض سجل الحضور والتأخير لآخر 14 يوم
- زر تسجيل حضور/انصراف من الجوال (مع موقع GPS تجريبي — الإصدار الكامل يحتاج حزمة `geolocator` لجلب الموقع الفعلي والتحقق من نطاق المدرسة)

**للمشرف/الإدارة — لوحة إدارة جديدة (مقابل الشاشة الرئيسية بالنظام المكتبي):**
- بطاقات إحصائيات اليوم (حاضر/متأخر/غائب/إجازة/لم يُسجَّل)
- قائمة كل المعلمين مع حالة اليوم لكل واحد
- تسجيل سريع لحالة أي معلم (حاضر/متأخر/غائب/إجازة بعذر/بدون عذر/استئذان) بلمسة واحدة
- فتح ملف معلم لعرض سجل حضوره لآخر 30 يوم (مقابل شاشة "جدول الدوام حضوري")
- الدخول يوجّه تلقائيًا: حساب معلم → شاشة المعلم، حساب مشرف/إدارة → لوحة الإدارة
- محمي بالصلاحيات (تم اختباره: حساب معلم يحاول يوصل لمسارات الإدارة يُرفض بـ 403)

**عام:**
- خادم منشور فعليًا على الإنترنت (Render) متصل بقاعدة بيانات PostgreSQL سحابية دائمة (Neon) — بدل الاعتماد على تشغيل محلي على جهازك

تم اختبار جميع مسارات الـ API فعليًا (تسجيل دخول صحيح/خاطئ، عرض البيانات، تسجيل حضور، الإحصائيات، التسجيل السريع، سجل معلم محدد، فحص الصلاحيات) قبل التسليم.

**لسه ما بُني بعد (المرحلة القادمة):** صفحة "سجلات وتقارير" التفصيلية (20+ نوع تقرير)، صفحة المسائلات، والإعدادات — راجع خارطة الطريق بوثيقة تحليل النظام بمشروعك على Claude.

## قبل الانتقال للإنتاج

1. **قاعدة البيانات**: تستخدم أصلاً PostgreSQL سحابية (Neon) بعد اتباع خطوات هذا الدليل — لا حاجة لتغيير إضافي هنا، فقط ترقية الخطة المجانية إذا كبر حجم البيانات.
2. **المفتاح السري**: تأكد إنك ضبطت `HADER_SECRET_KEY` بقيمة عشوائية طويلة خاصة بك بلوحة Render (وليس أي قيمة افتراضية).
3. **الموقع الجغرافي**: أضف حزمة `geolocator` في تطبيق الجوال، واطلب صلاحية الموقع من المستخدم، وتحقق من نطاق المدرسة في الخلفية قبل قبول تسجيل الحضور.
4. **ربط أجهزة البصمة**: تحتاج خدمة مزامنة خلفية منفصلة تقرأ من أجهزة ZKTeco الحالية (جدول `Machines`) وتغذي `attendance_events` — لم تُبنَ بعد في هذه المرحلة، وليست ضرورية بما إن القرار الحالي هو تسجيل حضور من الجوال مباشرة.
5. **البيانات التجريبية**: عطّل التعبئة التلقائية (`DISABLE_AUTO_SEED=1`) وابدأ بقاعدة فاضية فعليًا عند الانتقال من التجربة للاستخدام الحقيقي — هذا يتوافق مع قرارك بعدم ترحيل بيانات من Access والبدء من جديد.
